# ترخيص نسخة الدسكتوب 1.1

التفعيل جزء إلزامي من المثبّت NSIS: يبقى المثبّت منتظراً حتى استيراد ترخيص موقّع وإنشاء الحسابات أو تأكيد الإعداد الموجود. الإلغاء يعيد رمز فشل؛ لا يحذف قاعدة بيانات سابقة. حتى لو بقيت ملفات البرنامج بعد إلغاء التنصيب، لا يسمح المشغّل ببدء الخدمات بدون ترخيص صالح. إعادة تشغيل المثبّت تستأنف التفعيل والتجديد.

## إصدار التراخيص من حاسبة المالك

الأداة `scripts/License-Owner.ps1` توفر اختيارات إنشاء مفاتيح الإصدار، إصدار سنة، وإصدار مدى الحياة. تحتاج Node.js على حاسبة المالك فقط. شغّلها من PowerShell، وحدد الملفات عبر نوافذ الاختيار. لا تنقل هذه الأداة أو المفتاح الخاص إلى المختبر.

1. اختر إنشاء مفاتيح مرة واحدة. احفظ المفتاح الخاص المشفر بكلمة سر قوية ونسخة احتياطية منفصلة. فقدانه يمنع إصدار تجديدات للإصدارات التي تثق بمفتاحه العام.
2. ضمّن **المفتاح العام فقط** عند بناء نسخة الإنتاج. لا يوجد مفتاح إنتاج افتراضي أو خلفي في المستودع.
3. شغّل المثبّت عند المختبر، واحفظ طلب التفعيل. يحتفظ Windows بالمفتاح الخاص للجهاز؛ الملف يحتوي مفتاحاً عاماً وإثبات امتلاك، ولا يحتوي معلومات المرضى.
4. في أداة المالك اختر سنوي أو مدى الحياة، وحدد اسم المختبر وطلب الجهاز، واحفظ الملف بامتداد `.dllicense`.
5. استورد الملف داخل المثبّت، ثم أكمل إعداد الحسابات. لا تتطلب العملية اتصالاً بخادم البرنامج أو الموقع.

الترخيص السنوي يبدأ وقت إصداره وينتهي بعد سنة تقويمية. مدى الحياة لا يحمل تاريخ انتهاء ولا يحتاج تجديداً دورياً. هذا الإصدار لا يفرض مدة مستقلة للدعم والتحديثات. كل ترخيص لجهاز وحساب Windows واحد؛ إصدار جهاز آخر يتطلب طلباً وترخيصاً منفصلين. لا تختار النسخة عند المختبر نوع الترخيص بنفسها.

## حماية الجهاز والتشغيل

- الافتراضي مفتاح RSA داخل Microsoft Platform Crypto Provider / TPM، بصلاحية توقيع وغير قابل للتصدير. لا يعتمد على MAC Address.
- لا يتحول البرنامج تلقائياً إلى حماية أقل عند فشل TPM. يمكن للمالك بناء نسخة تسمح بربط برمجي عبر Windows CNG، ثم يجب أن يوافق صراحة عند إصدار الترخيص. هذا الخيار أضعف من TPM، ولا يصح تسويقه كحماية عتادية.
- يتحقق البرنامج من توقيع Ed25519، المنتج، قناة الإصدار، الجهاز، نوع الربط والمدة قبل تشغيل قاعدة البيانات. يثبت امتلاك مفتاح الجهاز بتحدٍ عشوائي عند كل تشغيل ودورياً.
- بوابة API المحلية تمنع الطلبات، بما فيها نتائج الأجهزة، إذا انتهى الترخيص أثناء الجلسة. لا يمسح البرنامج البيانات. احتفظ بالنسخ الاحتياطية الدورية قبل نهاية الاشتراك.
- ملف التفعيل وآخر وقت تحقق محميان بوسيلة Windows عبر Electron safeStorage، وخارج مجلد قاعدة البيانات والنسخ الاحتياطية. نسخ قاعدة البيانات لا ينقل الترخيص. استعادة البيانات على جهاز آخر تتطلب تفعيل الجهاز الجديد أولاً.
- تغيير الشبكة لا يغيّر مفتاح الجهاز. تغيير اللوحة، مسح TPM، حذف المفتاح أو تغيير حساب Windows قد يحتاج إصدار ترخيص جديد.
- مسح Setup لا يؤثر على التشغيل. الاحتفاظ بنسخة Setup مفيد للتجديد وإعادة التفعيل.

## بناء نسخة الإنتاج

على Windows وبعد تثبيت dependencies وتجهيز bundle وفق README:

```powershell
dotnet publish desktop/device/DeviceIdentity.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o desktop/licensing
node desktop/scripts/configure-license.cjs C:\Owner\issuer-public.pem production false
cd desktop
npm run build:win
```

`false` يشترط TPM. استخدام `true` يسمح بعرض طلب الربط البرمجي مع موافقة منفصلة عند الإصدار. لا تضبط ذلك دون اختيار واضح للمالك. ملف إعداد المفتاح العام وتجزئة مساعد الجهاز يُولدان محلياً ويدخلان أرشيف التطبيق. البناء يرفض إدراج مفاتيح خاصة أو تراخيص العملاء في ملفات التوزيع.

التنصيب الصامت يحتاج تفعيل سابق صالح أو `/LICENSE=C:\path\lab.dllicense`. يحتاج الملف أن يكون صادراً لمفتاح الجهاز وحساب Windows اللذين سيستخدمان البرنامج. إعداد الحسابات الأولية يتم من التنصيب التفاعلي؛ النمط الصامت مخصص لتحديث الأجهزة المُهيأة، لا لاستحداث حسابات بكلمات سر افتراضية.

## حدود الحماية وما يحتاج تجهيزاً منفصلاً

هذا تنفيذ **تفعيل بملف موقّع بدون خادم**. لا توجد بعد لوحة ويب للتراخيص، أكواد تفعيل أونلاين، إلغاء فوري عن بُعد أو سجل مركزي لعدد الأجهزة. طلب الجهاز ليس TPM attestation موثّقاً من خادم؛ يجب أن يصدر المالك التراخيص لعملاء وأجهزة يتحقق منها. لا تنشئ خدمة إصدار تلقائية اعتماداً على الطلب وحده.

إصدار بديل عند نقل ترخيص دائم لا يلغي النسخة القديمة أوفلاين؛ يجب إلغاء تفعيلها عملياً، أو إضافة خادم تحقق/سياسة اتصال إن أردت ضمان الإلغاء. كشف ترجيع الساعة محلياً يمنع التغيير البسيط فقط؛ استعادة صورة كاملة قد تعيد حالة الزمن. لا ندّعي منع تلاعب مسؤول الجهاز بنسبة 100%.

هذه الطبقة لا تشفّر كل كود Laravel/JavaScript ولا قاعدة البيانات الحية. أرشيف ASAR ليس تشفيراً. يتحقق الإصدار المجمّع من سلامة أرشيف ASAR ومن تجزئات ملفات bundle ومساعد الجهاز قبل بدء التشغيل، ويرفض الملفات المعدّلة أو المضافة. مفاتيح Node Options وتصحيح CLI معطّلة. يبقى RunAsNode مطلوباً لمراقب قاعدة البيانات؛ لا ندّعي منع مسؤول Windows من التحليل أو تعديل نسخة غير موقّعة. مقاومة تعديل المشغّل تحتاج توقيع إنتاج وسياسات Windows مناسبة. شهادة توقيع Windows غير مضمنة؛ يجب توفير شهادة الناشر وإعداد توقيع EXE والمثبّت قبل التوزيع التجاري. حماية كود PHP بمرمّز تجاري تحتاج ترخيص المرمّز وتحقيق توافق PHP 8.4 وكل وظائف المختبر؛ لم يُضف اعتماد تجاري غير متوفر ولم يُعطّل التشغيل لإخفاء ذلك.

GitHub Actions يصنع نسخة QA بمفتاح مؤقت، اسمها واضح وغير صالحة للبيع. المفتاح الخاص لا يُرفع في artifacts. نسخة QA لا تقبل تراخيص production والعكس. الفحوص السحابية تستخدم الربط البرمجي لأن TPM حقيقي غير مضمون على runner؛ قبول TPM يجب اختباره على جهاز Windows حقيقي قبل اعتماد إصدار الإنتاج.
