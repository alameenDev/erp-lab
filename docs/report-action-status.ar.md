# حالة إجراء التقرير الطبي

بدلاً من مؤشر الإرسال وحده، تظهر حالة تجمع ما نُفّذ: الطباعة، حفظ PDF، الإرسال، أو أي مجموعة منها. تظهر في قائمة التقارير والفواتير وتعديل النتائج وتفاصيل المريض. لكل إجراء وقت آخر تنفيذ بتوقيت بغداد يظهر عند الوقوف على المؤشر، وتسجّل التغييرات في سجل النشاط.

من نافذة التقرير: «طباعة مباشرة»، «حفظ PDF»، «إرسال واتساب»، «طباعة + حفظ»، و«حفظ + إرسال». تتجمع أيضاً الإجراءات المنفّذة بالتتابع. لا تغيّر المعاينة أو مجرد اختيار زر الحالة. «حفظ» هنا يعني تنزيل PDF، وليس حفظ نتائج التحاليل داخل البرنامج.

الطباعة تعني طلب نافذة الطباعة؛ المتصفح لا يؤكد خروج الورق أو يميّز الإلغاء. الإرسال يعني فتح محادثة واتساب بالطريقة الحالية مع تنزيل ملف الإرفاق؛ لا يؤكد إرسال الرسالة أو وصولها. تبقى تعليمات إرفاق الملف يدوياً. تنزيل PDF الخاص بالإرفاق ضمن خيار «إرسال واتساب» لا يضيف حالة حفظ مستقلة؛ خيار «حفظ + إرسال» يسجّل الاثنين صراحةً.

يسجّل الخادم الحالة بعد تنفيذ الإجراء في المتصفح، ويعيدها إلى الواجهة فوراً. فشل حفظ الحالة يظهر تنبيهاً ولا يعطي مؤشراً ناجحاً وهمياً. إذا نجح التنزيل ثم فشلت الطباعة أو المشاركة، يسجّل الحفظ فقط. يستخدم الخادم قفل الفاتورة لتجميع الإجراءات المتزامنة دون فقدان حالة سابقة. لا تتغير صلاحية الإرسال ولا حدود بيانات المختبر.

تضيف migration `2026_10_06_000001_add_report_action_status_to_invoices` ثلاثة أوقات اختيارية. تحتفظ الفواتير المرسلة سابقاً بحالتها من `sent_to_patient` دون اختراع أوقات قديمة. لا يُعاد تفسير `is_printed` القديم، لأنه مستخدم أيضاً ضمن نموذج تعديل النتائج.
