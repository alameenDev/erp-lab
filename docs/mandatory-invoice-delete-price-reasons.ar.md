# إلزامية أسباب الحذف والتغييرات المالية — Digital Lab

## النطاق والقاعدة الأساسية
لا ينفذ النظام الإجراءات الحساسة أدناه إلا بعد إدخال سبب مكتوب من المستخدم، بطول 10–1000 حرف. يتم التحقق على الخادم **قبل** تعديل البيانات؛ إخفاء النافذة أو استدعاء API مباشرة لا يتجاوز الشرط.

| العملية | سبب مطلوب؟ | إشعار للمالك |
|---|---|---|
| حذف فاتورة بالكامل | نعم | نعم |
| حذف تحليل من تفاصيل الفاتورة، بما في ذلك الكروبات والباقات | نعم | نعم |
| حذف تحليل من كتالوج المختبر | نعم | نعم |
| تعديل سعر تحليل داخل فاتورة | نعم | نعم |
| تعديل إجمالي الفاتورة أو مجموعها قبل الخصم | نعم | نعم |
| تعديل قيمة/نوع خصم فاتورة قائمة | نعم | نعم |
| خصم يدوي عند إنشاء فاتورة جديدة | نعم | السبب محفوظ في سجل النشاط |
| تعديل السعر الأصلي أو سعر المريض لتحليل في الكتالوج | نعم | نعم |
| تغيير نتائج التحاليل الاعتيادي بدون تغيير الأسعار أو حذف عناصر | لا | نظام الإشعارات الاعتيادي كما هو |

## طريقة الإدخال
- في شاشة الفواتير أو التحاليل: عند اختيار الحذف تظهر نافذة سبب إلزامي؛ زر الإلغاء يغلق بدون إجراء.
- في شاشة تحرير الفاتورة: خانة واضحة بعنوان «سبب حذف تحليل أو تعديل السعر أو الخصم». عند محاولة الحفظ، يرفض الخادم التعديل الحساس إذا كان التعليق غير كاف.
- في شاشة تعديل تعريف التحليل: خانة سبب تغيير سعر التحليل.
- المطلوب سبب واقعي ومحدد. كتابة أحرف حشو ليست مناسبة، لكن لا يمكن للنظام تحديد صدق السبب آلياً.

## ما يُحفظ وما يظهر للمالك
- سبب المستخدم الأصلي، مع قائمة العمليات الحساسة مشتقة من التغييرات التي تحقق منها الخادم، في Activity Audit وSnapshot لأرشيف الفواتير.
- بعد الحذف، يُحفظ كشف ثابت يحتوي على رقم وباركود الفاتورة واسم المريض ورقمه وعمره وجنسه وعنوانه إن كانت البيانات متاحة، وبيانات الفحوص والأسعار والنتائج السابقة والمبلغ والدفعات.
- إشعار داخل بوابة المالك يوضح السبب والموظف والتاريخ والهوية المطلوبة، وزرّاً إلى تفاصيل سجل التغيير عند توفره.
- إشعارات الهاتف المختصرة لا تعرض اسم المريض أو السبب الطبي على شاشة القفل؛ التفاصيل محفوظة في صندوق المالك بعد تسجيل الدخول.
- السجلات السابقة التي لا تتضمن سبباً لا يمكن اختراع مبرر تاريخي لها؛ تعرض كـ «غير مسجل».

## التنفيذ التقني
- `App\\Services\\InvoiceChangeReason`: يحسب فرق الأسعار/الخصومات وعمليات الإزالة من البيانات المحفوظة مقابل الطلب، ويتحقق من `change_reason` قبل أي كتابة.
- `AuditTrail`: يسجل `change_reason` وقائمة `reason_operations` على العملية الفعلية.
- `InvoiceChangeArchive`: يحتفظ بسبب التعديل والحذف كدليل غير قابل للتعديل من واجهة المالك.
- `OwnerNotifications`: يرسل إشعاراً عند حذف فاتورة أو تحليل أو تعديل حساس حتى لو بقي إجمالي الفاتورة ثابتاً.
- لا توجد تغييرات بنيوية لقواعد البيانات في هذه الإضافة.

## فحص قبل النشر
راجع نتائج CI لـ `InvoiceMutationReasonsTest` و`OwnerNotificationTest` و`ActivityAuditTest` و`OwnerPortalTest` وواجهة Vue. يستحسن التأكد عملياً من إنشاء فاتورة بخصم، تعديل سعر تحليل، حذف تحليل من فاتورة، حذف فاتورة، ثم مراجعة إشعار المالك على سطح المكتب والهاتف.
