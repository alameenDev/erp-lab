# تطبيق بوابة المالك والإشعارات

تضيف هذه النسخة سجلاً دائماً لإشعارات المالك، وإشعار Web Push عند حذف فاتورة أو تغيير إجمالي مبلغها، وملخصاً مستقلاً لكل مختبر عند الساعة **00:05 بتوقيت بغداد** عن اليوم السابق. الرسالة تحتوي رقم الفاتورة واسم المنفذ والقيمة قبل وبعد؛ لا تحتوي أسماء المرضى أو نتائجهم. فتح التفاصيل يتطلب تسجيل الدخول والصلاحية الحالية للمختبر.

## تشغيل النسخة بعد الدمج

1. انشر backend وملفات frontend الناتجة من `npm ci && npm run build` معاً عبر طريقة النشر المعتادة. يجب أن تعمل روابط `/owner-portal/*` بمسار SPA fallback، وأن تُقدَّم الملفات الموجودة فعلياً أولاً، خصوصاً `/owner-portal-sw.js` بنوع JavaScript و`/owner-app/manifest.webmanifest` بنوع JSON أو manifest. لا ترجع صفحة HTML بدلاً من هذه الملفات.
2. شغّل `php artisan migrate --force` و`php artisan optimize:clear`.
3. شغّل `php artisan portal:push-setup` مرة واحدة. يُستخدم نفس مفتاح VAPID الموجود لخدمة المرضى؛ الأمر لا يدوّر المفتاح. احتفظ بملف `storage/app/private/portal-push-vapid.json` بين النشرات، خارج الملفات العامة، وبنفس `APP_KEY` المستخدم لتشفير اشتراكات الأجهزة.
4. تأكد من `PORTAL_PUSH_ENABLED=true` ومن `PORTAL_PUSH_SUBJECT` برابط HTTPS حقيقي أو `mailto:` صالح، ومن توافر اتصال الخادم الخارجي بخدمات Push الخاصة بالمتصفحات.
5. يجب أن يعمل Laravel Scheduler كل دقيقة، بمسار PHP ومجلد المشروع الصحيحين، مثلاً:

   ```cron
   * * * * * cd /absolute/path/to/backend && /usr/bin/php artisan schedule:run >> /dev/null 2>&1
   ```

   إذا كان السطر موجوداً بالفعل فلا تضف نسخة ثانية. المجدول يشغّل `owners:daily-summary` و`owners:deliver-notifications --limit=20` تلقائياً. يُعاد الإرسال المؤقت بحد أقصى خمس محاولات. عند تشغيل عدة خوادم اجعل المجدول على خادم واحد أو استخدم قفل cache مشتركاً.

## تجربة الاستلام الفعلي

من حساب المالك افتح **التطبيق والإشعارات**، ثبّت البوابة ثم اختر تفعيل الإشعارات، ثم **إرسال إشعار تجريبي**. يفترض أن تُعالج الرسالة عند الدقيقة التالية. قبول مزود Push للرسالة ليس دليلاً على أن المستخدم قرأها؛ سجل القراءة منفصل. يمكن تنفيذ `php artisan owners:deliver-notifications` يدوياً للتشخيص. عند الحاجة راجع حالة `owner_push_deliveries` وحقل آخر تشغيل في إعدادات الإشعارات، دون طباعة مفاتيح الأجهزة أو بيانات الاشتراك في السجلات.

على iPhone وiPad يلزم iOS/iPadOS 16.4 أو أحدث: Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية، ثم افتح الأيقونة وفعّل الإشعارات. على Android والمتصفحات الداعمة يظهر زر التثبيت أو خيار التثبيت من قائمة المتصفح. التطبيق يحتاج الإنترنت لعرض البيانات؛ لا تُخزَّن بيانات المرضى أو الحسابات المالية للاستخدام بلا اتصال. تبقى شاشة تسجيل دخول المالك داخل نطاق التطبيق.

## الملخص والأرقام

- المرضى: عدد المرضى المختلفين، والزيارات: عدد الفواتير غير المحذوفة المسجلة في يوم بغداد المحدد. التحاليل تشمل مكونات الكروبات والباقات، وفق خدمة التقارير الحالية.
- المدفوع والمتبقي: لفواتير ذلك اليوم، من دفتر الدفعات، مع استبعاد الدفعات المسجلة بعد نهاية اليوم. **التحصيل خلال اليوم** مستقل ويشمل تسديد ديون أقدم.
- الإحالات: عدد الفواتير المحالة مرة واحدة حتى لو تضمنت طبيباً ومختبراً. يظهر تفصيل إحالات الأطباء والمختبرات أيضاً.
- يشمل الملخص النتائج المكتملة وغير المكتملة، وعدد وقيمة المحذوفات، وزيادات وتخفيضات التعديل.
- الملخص لقطة لا تُعاد كتابتها، وفق البيانات المتاحة عند إعداده. إذا تأخر المجدول ثم عُدّلت/حُذفت فواتير سابقة قبل إعداد الملخص، فقد تختلف عن حالتها الأصلية عند منتصف الليل؛ يبقى سجل العمليات مرجعاً للتغييرات. هذه ليست عملية إغلاق محاسبي أو إعادة بناء تاريخي لكل نسخة فاتورة.
- منع التكرار لكل مالك/مختبر/يوم. يبدأ من يوم تفعيل هذه النسخة أو إنشاء حساب المالك، ولا يرسل الأرشيف القديم. يعوّض تلقائياً آخر ثلاثة أيام عند انقطاع المجدول. لتعويض يوم أقدم بعد تاريخ التفعيل: `php artisan owners:daily-summary --date=2026-10-27` ثم شغّل عامل الإرسال. لا يقبل اليوم الحالي أو المستقبل.

## التحكم بالأجهزة والحسابات

الاختيارات مستقلة لكل جهاز: إشعارات تغييرات الفواتير وملخص اليوم. إيقافها لا يمس سجل الإشعارات في البوابة. يستمر الإرسال عند إغلاق التطبيق أو انتهاء جلسة الدخول العادية؛ تسجيل الخروج الصريح يوقف اشتراك الجهاز الحالي، وتغيير كلمة المرور أو تعطيل/حذف حساب المالك يلغي جميع أجهزته. ربط حساب آخر بالجهاز يحتاج تفعيل الإشعارات صراحة، ولا تُنقل إليه رسائل الحساب السابق. التحقق من ملكية المختبر يحصل عند عرض السجل وعند الإرسال، ويتوقف الإرسال بعد إزالة الربط. الرسائل التي قبلها مزود Push بالفعل لا يمكن سحبها من خدمته؛ عامل التطبيق يتحقق من الحساب المرتبط قبل عرضها.

اختبارات CI تغطي الحسابات والحدود المالية ومواعيد بغداد وعدم التكرار وتشفير الاشتراكات والعزل والتراجع وإلغاء الأجهزة، واختبارات المتصفح تغطي الواجهة على الجوال والكمبيوتر والتفعيل والاختيارات والروابط. التسليم الفعلي على أجهزة iPhone وAndroid وفحص Cron على الاستضافة يحتاجان تجربة بعد النشر؛ لا يُعد اختبار المحاكاة إثباتاً لوصول إشعار حقيقي.
