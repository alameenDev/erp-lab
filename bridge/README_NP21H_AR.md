# Digital Lab — NP-21H

نسخة خاصة بنقل نتائج NP-21H عبر HL7 2.3.1 / MLLP. تم بناء المحلل على رسالة الجهاز الفعلية، ويتطلب اختبار قبول على الجهاز قبل الاستخدام اليومي.

## 1. تحديث الموقع أولاً

يُنشر تحديث النظام من PR #29 مرة واحدة (الخادم والواجهة معاً)، ثم شغّل `php artisan optimize:clear` من مجلد backend. يفترض وجود تحديث bridge السابق وترحيله؛ لا حاجة لترحيل جديد لهذا التغيير. بعد ذلك تتم إدارة المختبر والموديل وكود CBC من صفحة الأجهزة بدون تعديل ملفات لكل مختبر. رفع ملفي الخادم من الحزمة القديمة وحدهما لا يضيف واجهة الإعداد الجديدة.

من صفحة الأجهزة أنشئ سجلاً مستقلاً للجهاز: اختر مختبر العاصمة إذا كنت مدير النظام (حساب المختبر ينسب الجهاز لمختبره تلقائياً)، ثم Analyzer Model = Nipigon NP-21H، وCBC Interface Code = 12345678، وResult Handling = Match barcode and fill invoice draft. خذ API Token الخاص بهذا الجهاز. يجب أن يكون تحليل Complete Blood Count (CBC) في مختبر العاصمة مضبوطاً بنفس كود الربط. يبقى جهاز DxH 500 لمختبر الفرات بإعداداته ومفتاحه المستقلين.

## 2. تشغيل Windows

افتح DigitalLabBridge-NP21H.exe. أدخل عنوان API الحالي لموقعك ومفتاح الجهاز الجديد. لا تضع كلمة مرور MySQL.

- API URL: عنوان الموقع وينتهي بـ /api.
- Listen IP: 0.0.0.0
- Analyzer IP: 192.168.1.80 حسب سجل الاختبار؛ غيّره إذا تغيّر IP الجهاز.
- Port: 5600 مطابق لصورة LIS.
- اضغط فحص السيرفر وحفظ الإعدادات ثم تشغيل.

إعدادات وبيانات هذا الإصدار مستقلة في `%LOCALAPPDATA%\DigitalLabBridge-NP21H` ولا تستخدم مفتاح أو طابور DxH.

## 3. إعدادات الجهاز للاختبار والاستقبال أحادي الاتجاه

في LIS Communication:
- IP Address: عنوان الكمبيوتر الحالي (192.168.1.100 إذا لم يتغيّر).
- Port: 5600.
- Auto-communication: مفعّل.
- Communication Acknowledgement: مفعّل؛ ACK timeout: 10 ثوانٍ.
- Bidirectional LIS/HIS Communication: أوقفه لهذا الإصدار، إذ لا يرسل طلبات فحوصات أو بيانات مرضى إلى الجهاز.
- Enable Heartbeat Test: أوقفه لهذا الإصدار، إذ لم تُوثق رسالة heartbeat الخاصة بالجهاز.
- Histogram Transmission Method: Not transmit؛ لا تُنشأ رسوم تخمينية من الأرقام.
- Apply ثم Reconnect بعد تشغيل الوسيط.

هذه تغييرات لعزل إرسال النتائج المدعوم، وليست دعماً لجميع أوضاع الاتصال. ضع باركود الفاتورة في Sample ID. نستخرجه حصراً من OBR-3؛ لا نطابق الاسم أو العمر.

## النتائج

العنوان: Complete Blood Count (CBC).
الأعمدة: Test / Result / Unit / Reference Range.

الترتيب: WBC, LYM%, GRAN%, MID%, LYM#, GRAN#, MID#, RBC, HGB, HCT, MCV, MCH, MCHC, RDW-CV, RDW-SD, PLT, MPV, PDW, PCT, P-LCR, P-LCC.

القيم والوحدات والمديات تحفظ كما أرسلها الجهاز؛ لا تحويل وحدات ولا تقريب. GRAN وMID لا تُحوّل إلى NE أو MO. العمر وTake Mode وBlood Mode وRef Group بيانات وصفية وليست صفوف تحاليل. العلامات والتعليقات وتواريخ التحليل تبقى في تفاصيل رسالة الجهاز. تميّز المراجعة اختلاف تاريخ النتيجة عن تاريخ إرسالها.

تملأ النتائج فاتورة واحدة ذات باركود مطابق داخل المختبر، بشرط وجود تحليل CBC واحد بكود 12345678 وعدم وجود نتائج سابقة أو اعتماد/إرسال للفاتورة. الحالات الملتبسة تبقى للمراجعة. النتائج مسودة ولا تُعتمد أو تُرسل للمريض تلقائياً.

## التأكيد ومنع التكرار

AA يعني أن رسالة مكتملة قابلة للتحليل حُفظت في الطابور المحلي الدائم، حتى أثناء انقطاع الإنترنت. حالة «تأكد الحفظ بالسيرفر» مع رقم السجل هي تأكيد التخزين على الموقع. عند فشل القرص لا يرسل البرنامج AA. الرسائل الناقصة أو ذات فحص مجهول أو حالة غير F تُحفظ للمراجعة ولا تُستورد كأنها نتائج صحيحة.

إعادة إرسال نفس النتيجة بنفس محتواها ومعرّف الرسالة لا تضيف نتيجة ثانية، حتى لو تغيّر وقت MSH-7. تغيير قيمة أو وقت التحليل يحتفظ برسالة جديدة للمراجعة، ولا يستبدل نتيجة الفاتورة السابقة تلقائياً.

الاتصال الصامت يبقى مفتوحاً؛ مهلة 30 ثانية تخص إطاراً بدأ ولم يكتمل فقط.

## اختبار القبول

1. أرسل نتيجة معروفة بباركود فاتورة اختبار تحمل CBC بكود 12345678.
2. تحقق من ظهور 21 نتيجة ومطابقة كل قيمة ووحدة ومدى مع الجهاز.
3. تأكد من حفظ محلي وACK AA ثم تأكيد السيرفر ورقم السجل.
4. أعد إرسال نفس النتيجة وتأكد من عدم تكرارها.
5. افصل الإنترنت مع بقاء الشبكة المحلية ثم أرسل نتيجة اختبار أخرى؛ بعد عودته تأكد من رفعها.
6. أغلق وافتح الوسيط وتأكد من بقاء الطابور. جرّب باركوداً غير موجود للتحقق من بقائه في الوارد.

ملفات المصدر تعمل عبر START_NP21H.cmd عند تثبيت Python 3.10+ مع Tkinter. بناء exe يتم على Windows في GitHub Actions.
